# زهى الأعمال — نظام إدارة خدمات النظافة والتشغيل والصيانة

MVP قابل للتشغيل مبني على المخطط الكامل (Master Blueprint) اللي زودتني فيه: React 19 +
TypeScript + Tailwind CSS v4 من جهة الواجهة، وExpress + Node.js من جهة الخادم، بواجهة عربية RTL
كاملة.

## وش اللي شغّال فعلياً الآن (MVP)

- **تسجيل دخول تجريبي بالأدوار الخمسة** (مدير عام، مدير نظام، مشرف إداري، مشرف ميداني، فني ميداني)
  بدون كلمة مرور — لتسريع التطوير. راجع قسم "المرحلة القادمة" تحت.
- **لوحة تحكم**: عدد مواعيد اليوم، العقود السارية، إجمالي المصروفات، التحصيل، ورسم بياني للإيرادات.
- **جدول المواعيد**: تجميع حسب اليوم مع اسم اليوم بالعربي، تبويبات "جدولي" / "الجدول العام" /
  جدول كل مشرف، وعرضين (جدول / تقويم مبسّط).
- **محرك العقود الدوري**: عند إنشاء عقد جديد (تكرار أسبوعي / نصف شهري / شهري) يتم توليد كل زياراته
  تلقائياً وحقنها في جدول المواعيد العام، مرتبطة برقم العقد والمشرف والفنيين.
- **المصروفات والعُهد**: تسجيل مصروف بالتصنيفات المطلوبة (عُهد، وقود، مواد تنظيف، رواتب،
  إقامات وتأشيرات، صيانة سيارات) + ملخصات يومية/شهرية/سنوية.
- **المبيعات والفواتير**: إصدار فاتورة مع احتساب ضريبة القيمة المضافة 15٪ تلقائياً وتتبّع حالة السداد.
- **بوابة الفني الميداني**: واجهة مخصصة للجوال — فتح موقع العميل بخرائط جوجل، رفع صور قبل/بعد،
  تحديث حالة الزيارة خطوة بخطوة، وتسجيل التحصيل الميداني.
- **تخزين بسيط (JSON على القرص)** في `data/data.json` مع بيانات تجريبية مبدئية (مشرفين، فنيين،
  عملاء، خدمات، عقد وموعد نموذجي) — بديل مؤقت لقاعدة بيانات حقيقية.

## المرحلة القادمة (غير مُنفَّذة بعد — التالي على القائمة)

- مصادقة حقيقية (بريد/كلمة مرور أو OTP) بدل تسجيل الدخول التجريبي.
- قاعدة بيانات حقيقية (Postgres / Supabase) بدل ملف JSON — طبقة `src/server/store/db.ts` مبنية
  بحيث يسهل استبدالها دون تغيير الراوترات.
- تقويم شهري/أسبوعي بصري كامل (حالياً معروض كتجميع حسب اليوم).
- تاريخ هجري بجانب الميلادي.
- ربط رفع الصور بتخزين سحابي حقيقي (حالياً تُحفظ كـ base64 داخل ملف JSON — غير مناسب لحجم إنتاجي كبير).

## التشغيل محلياً

```bash
npm install
npm run dev
```

يفتح على `http://localhost:3000`. عند أول تشغيل تتكوّن بيانات تجريبية تلقائياً داخل `data/data.json`.

## البناء والتشغيل الإنتاجي

```bash
npm run build
npm start
```

## النشر على Vercel

المشروع مهيأ للنشر الصفري الإعداد (zero-config) على Vercel:
- `vercel.json` يبني الواجهة بـ `vite build` ويوجّه `/api/*` إلى دالة سيرفرلس واحدة في `api/index.ts`،
  وأي مسار آخر إلى `index.html` (لأن التنقل بين الصفحات يتم بالكامل من جهة العميل عبر React Router).
- **تنبيه مهم**: طبقة التخزين حالياً ملف JSON، وعلى Vercel يُكتب مؤقتاً في `/tmp` لأن نظام الملفات
  غير قابل للكتابة في أي مكان آخر. هذا يعني **البيانات لا تبقى بين الطلبات المختلفة** على الإنتاج
  (كل دالة سيرفرلس قد تبدأ من نسخة جديدة) — مناسب لعرض الواجهة والتجربة فقط، وليس للاستخدام الفعلي.
  الخطوة التالية الحقيقية هي ربط قاعدة بيانات دائمة (Postgres / Supabase) بدل `src/server/store/db.ts`.

## عبر Docker

```bash
docker build -t zaha-ops .
docker run -p 3000:3000 zaha-ops
```

## البنية

```
src/
  shared/types.ts      # النماذج المشتركة (Profile, Contract, Appointment, Expense, Invoice...)
  server/
    index.ts           # Express + Vite middleware (dev) / static (prod)
    routes/api.ts       # كل نقاط الـ API + محرك توليد زيارات العقود
    store/db.ts         # طبقة تخزين JSON (قابلة للاستبدال بقاعدة بيانات)
  client/
    pages/              # الصفحات: لوحة التحكم، المواعيد، العقود، المصروفات، المبيعات، العملاء، بوابة الفني
    components/          # Layout (الشريط الجانبي RTL)، شارات الحالة
    lib/                 # auth (سياق تسجيل الدخول)، api (fetch wrapper)، date (تنسيق عربي)
```
